# 进程管家 · fnproc

> 机器为什么变慢、8080 被谁占了、哪个服务又挂了 —— 打开一个页面全看清，还能直接处置。

![进程管家](app/ui/images/icon_256.png)

进程管家是给飞牛 fnOS 做的**进程与系统资源管理器**：把平时要 SSH 上去敲 `top`、`ss`、`systemctl` 才能看到的东西，做成一个打开就能用的网页。看到问题，点两下就能处理，每一步都会留下记录。

---

## 它解决哪些麻烦

- **机器突然变慢**，不知道是哪个进程在吃 CPU 或内存
- **装应用提示端口被占**，却查不到是哪个程序占着
- **某个服务悄悄挂了**，得连 SSH 敲命令才知道
- **想停掉一个卡死的进程**，还要确认 PID、记着信号名
- **出问题想复盘**：「刚才谁重启过服务？」日志里翻半天也找不到

这四件事在进程管家里都是一两下点击的事，而且都会记进操作记录，随时能查。

## 功能一览

六个页面，顶部关键指标条始终可见。

### 📈 概览 —— 一眼看清整机状态

- 六项关键指标：CPU、内存、Swap、负载、进程数、磁盘读写与网络收发
- 三张趋势曲线：CPU、内存 + Swap、磁盘 + 网络
- 时间范围随手切：最近 60 秒 / 10 分钟 / 1 小时 / 6 小时 / 24 小时 / **7 天**，窗口越长自动按更粗粒度聚合（最长跨度仍保持约 240 个点，曲线不会挤成一团）
- 历史数据自动留存 **7 天**，按时间滚动清理，重启应用、升级版本都不清空

### ⚙️ 进程 —— 谁在吃资源

- **列表**：按 CPU / 内存 / PID 排序，输入关键字即时筛选
- **树形**：按父子关系展开，父进程直接显示整棵子树的 CPU 与内存合计，一眼看出「这个服务全家吃了多少」
- **详情**：CPU、内存 **RSS / PSS / 独享 / 共享 / Swap** 五种口径、虚拟峰值、线程列表（名称与 TID）、打开的文件数与上限、OOM 分数与调整值、磁盘读写、CPU 时间、父进程链、所在控制组（cgroup）及其内存额度、环境变量（敏感项自动打码）、命令行与所在目录、子进程
- **处置**：支持 9 种信号（结束、暂停、继续、重载等），点一下就能发；**可连同整棵子树一起结束**（先子后父，不留孤儿进程）

### 🔌 端口 —— 端口到底被谁占了

列出所有监听中的端口，并把每个端口对应到具体的进程、用户和容器。装应用撞端口时，来这里看一眼就知道该找谁。

### 📦 容器 —— Docker 里在跑什么

按容器聚合进程数、CPU、内存、线程数，点一下只看某个容器里的进程。

### 🛠 服务 —— 系统服务直接启停

列出全部 systemd 服务，运行中、未运行、失败一目了然，失败项标红。可以就地启动、停止、重启 —— 不用再开终端。

关键系统服务（SSH、网络、systemd 自身、定时任务等）的停止与重启按钮会置灰，只允许「启动」—— 防止手滑把自己锁在门外。

### 📝 记录 —— 每一步都有账可查

发信号、启停服务、应用自身启动停止，以及**被拒绝的尝试**，全部记下来，可追溯：

- 按操作类型、结果（成功 / 拒绝 / 失败）筛选，或直接搜关键字
- 顶部汇总显示总条数与结果分布
- 记录写在本地数据库里，**重启、崩溃、断电都不会丢**，也不会被自动清理

## 关于安全与克制

- **不联网**：除安装/升级时向作者上报一次「版本号 + 设备指纹」（用于装机量统计，可在 `cmd/lib/feishu_push.sh` 里关闭）之外，应用不连接任何外部服务，不采集、不上传任何运行数据
- **只看本机**：读的是系统自带的进程与资源信息，不碰你的照片、文档、影音文件
- **零额外依赖**：除应用本身，不会往你的 NAS 上装任何东西
- **危险操作有护栏**：
  - 系统 1 号进程与进程管家自己，不允许结束
  - 关键系统服务只允许启动，不允许停止或重启
  - 所有结束进程、启停服务的操作都需要二次确认
  - 每一次尝试（包括被拦下的）都会写进操作记录

## 快速上手

1. 在应用中心安装后打开**进程管家**
2. 首页「概览」就能看到整机 CPU、内存与趋势曲线
3. 机器卡顿时切到「进程」，按 CPU 排序，点那一行看详情，需要时发信号处理
4. 装应用提示端口占用时，切到「端口」搜端口号，直接看到是哪个进程
5. 想确认刚才做了什么，切到「记录」即可

## 数据存在哪

| 内容 | 位置 | 说明 |
|---|---|---|
| 历史曲线 | 应用数据目录 `data/history.db` | 按时间保留 7 天，超出自动滚动清理；从旧版本升级时会自动迁移 `history.jsonl` 里的历史 |
| 告警规则与事件 | 应用数据目录 `data/alerts.db` | 规则、触发记录、看门狗配置 |
| 操作记录 | 应用数据目录 `data/audit.db` | 只增不删，重启、断电都不丢 |
| 进程快照 | 应用数据目录 `data/snapshots.db` | 手动存的快照，用于前后对比 |
| 运行日志 | 应用数据目录 `info.log` | 启动与异常记录 |

这些文件都在应用自己的数据目录里，全部只在本机，不涉及云同步。

## 卸载时会怎样

卸载时向导会问你怎么处理数据，两个选择都会**先把采集进程停干净**、删掉运行时 socket，不留半停状态：

- **保留数据（推荐）**：上面那几个数据库原样留在原处，重新安装同一应用后，历史曲线、告警规则、操作记录、快照都能接着用
- **删除全部数据**：连库带日志一起删掉，不可恢复

另外可以勾选「同时清理本应用产生的桌面通知」，把进程管家此前推送到飞牛通知中心的告警一并清掉 —— 不清理的话，卸载后这些通知点开也无处可去。这个选项**默认不主动删除**：只有你在向导里明确勾选才会清，字段缺失或为空时一律保留，宁可留几条可手动删的通知。

想先看看会删什么，可以先演练一遍（只打印动作、不动任何文件）：

```bash
sudo -u root env FNPROC_UNINSTALL_DRYRUN=1 \
  TRIM_PKGVAR=/vol3/@appdata/fnproc \
  TRIM_APPDEST=/vol3/@appcenter/fnproc \
  wizard_data_action=delete wizard_clear_notify=true \
  bash /var/apps/fnproc/cmd/uninstall_callback
```

> 卸载脚本只在「应用数据目录确实是本应用的那一个」时才执行删除，路径形态不符会直接拒绝并在日志里写明原因，不会因为环境变量异常而删错目录。

## 常见问题

**问：图表一直是空的？**
答：曲线需要累计几秒数据才会画出来，打开后稍等 2～3 秒。若是长时间空白，先确认应用是「运行中」，再刷新页面。

**问：为什么有些进程的端口看不到？**
答：容器内的进程使用自己的网络空间，它的端口不会出现在主机侧，这是系统隔离的正常结果。

**问：为什么关键服务的停止按钮是灰的？**
答：这些服务一旦停掉，NAS 可能失联或系统异常，因此只开放「启动」。

**问：记录会不会越攒越多、把盘撑满？**
答：单条记录很小（几百字节），日常操作一天也就几十条。记录按你的要求不会自动删除，长期运行也只占几 MB。

**问：会拖慢 NAS 吗？**
答：采样每秒一次且只读系统信息，常驻内存占用很小，正常使用几乎察觉不到。

### v0.4.0

- **批量处置**：进程列表每行可勾选，选中后顶部出现操作条，一次对多个进程发 SIGTERM / SIGKILL。服务端同样有硬约束（一次最多 50 个、不支持整棵子树、必须显式确认），每条结果分别落操作记录，部分成功也会明确告诉你成功几个失败几个
- **关注的服务**：服务列表每行前面多了一颗星，点一下加入关注，关注的服务自动排到最前 —— 239 个服务平铺时，日常盯的那几个能被一眼找到
- **进程追踪**：给一个关键字（进程名或命令行片段），记住当下的进程清单，之后有新进程冒出来就记一条。适合盯「某服务是不是被偷偷重启了」「某个 worker 是不是反复重生」。**只观察、只记录，不执行任何命令**
- **曲线上标出操作时间点**：概览的 CPU 曲线会标出这段时间里发生的操作（发信号、服务启停、改关注、批量处置），被拒绝的操作单独用红色区分。内存暴涨的时间点从此能直接对上「那一刻谁动过什么」
- 操作记录、告警、追踪、快照四类数据都留在应用数据目录，重启与升级不丢
- **按用户聚合**：进程页多一个「按用户」视图，按 UID 汇总进程数 / CPU / 内存 / 线程，附 CPU 占比条，多用户机器上直接看出谁在吃资源
- **磁盘 IO 排行**：概览页列出读写累计最多的进程（数据取自 `/proc/<pid>/io` 的真实落盘字节，不含页缓存）
- **告警规则模板**：新建规则时可一键套用「CPU 持续过高」「内存过高」「Swap 过高」「磁盘空间不足」「OOM 杀进程」「内存压力过高」，套用后仍可继续改，省掉手填阈值/持续/冷却还填反方向
- **开机耗时条形图**：把 `systemd-analyze blame` 的文本列表画成横向条形，一眼看出第二名只有第一名的一半；内核启动单独标色
- **手机端卡片式列表**：容器表与服务表在窄屏下每行摊成卡片（星标/名称/状态/操作各占一行），不用横向滚动就能点到按钮；进程表列多，保留表格并把操作列钉在右侧

### v0.3.0

- **🔔 告警**：新增告警页。可对 CPU / 内存 / Swap / 磁盘 / 内存压力 / 进程消失 / 服务 failed / OOM 设置规则，**持续超标才提醒**、提醒后进入冷却不会刷屏。通知直接落到飞牛桌面通知（铃铛），也可以再填一个 Webhook。每条提醒的投递结果（成功 / 失败原因）都记在事件表里，出问题能查

- **📦 容器详情**：容器页显示真实的容器 CPU / 内存 / 网络 IO（来自 `docker stats`），并能看容器日志、重启、停止

- **📊 概览新增两张卡**：资源压力（PSI：CPU/内存/IO 到底有没有让进程排队等待，比 CPU% 更能说明「为什么卡」）与各卷用量（含 inode）
- **🐕 看门狗**：监视的进程不在了就执行一条命令把它拉回来。默认不启用，界面明确标注命令以 root 执行
- **📤 数据外带**：进程 / 历史 / 操作记录 / 告警事件都能导出 CSV（Excel 打开不乱码），并提供 Prometheus `/metrics`
- **开机耗时**：`systemd-analyze` 的内核/用户空间耗时与最慢的服务排行
- 进程与树形视图改成按行复用节点，刷新不再整表重建；手机上详情抽屉的长区块默认折叠

### v0.2.1

- **响应瘦身**：接口自动压缩，进程列表 100 KB → 15 KB（省 85%）、服务列表 32 KB → 4.7 KB、历史曲线 27 KB → 6 KB；静态文件带 ETag，没变就直接返回 304，不再每次重下 57 KB 的脚本和 30 KB 的样式
- **实时推送瘦身**：每秒一帧的实时数据从约 16 KB 降到约 1.8 KB（省 89%）——原来每帧都夹带一整份进程列表，而页面从来没用到它
- **刷新更省**：进程列表从每 3 秒重拉改成 10 秒兜底（实时数字仍走推送），页面切到后台时完全不刷新；表格改成按行更新，滚动位置不再跳动、正在点的按钮也不会被重建
- **没人看就降频**：没有页面连接时，进程扫描从每秒一次降到 10 秒一次，端口归属从 10 秒降到 60 秒。实测程序自身占用从 **3.1% CPU 降到 0.8%（空闲）/ 2.4%（有人看）**
- **不再卡住界面**：服务启停与容器查询改成异步执行。以前一个卡住的 `systemctl` 会让整个页面最长 20 秒没有任何响应
- **端口归属更快**：改用内核一次性给出的 `ss` 结果，替代每轮上万次 `/proc` 文件读取；实测结果与旧实现完全一致（143 条端口归属，零差异）

### v0.2.0

- **进程详情更有据可依**：新增 PSS / 独享（USS）/ 共享内存三个内存口径 —— 只看 RSS 会把共享库重复计入每个进程，同一台机器加起来能虚高两三成，现在能看出「真正占了多少」。同时补上线程列表、父进程链、所在控制组及其实时内存额度、打开文件数上限、OOM 分数调整值，环境变量里的密钥、口令、令牌自动打码后展示
- **结束整棵子树**：面对 node、python 这类「主进程 + 一堆 worker」的服务，以前要一个一个结束，还容易留下孤儿进程继续跑；现在一次结束整棵树，顺序是先子后父，弹窗里会先告诉你一共有几个子孙进程
- **历史曲线最长可看 7 天**：历史记录从按文件增长改成按时间保留（默认 7 天），1 小时 / 6 小时 / 24 小时 / 7 天都能看，跨度越长自动按更粗粒度聚合，页面上的时间轴提示会写清聚合粒度；同时去掉了旧方案在文件写满时整份重写的卡顿
- 顺手修掉一处时间轴歧义：跨天查看曲线时，起止时间现在带日期，不再出现「起点比终点还晚」的错觉

### v0.1.1

- 记录页面升级：按操作与结果筛选、关键字搜索、分页浏览，顶部显示总条数与成功 / 拒绝 / 失败分布
- 服务操作的结果区分「被规则拦下」与「执行了但失败」，两种情况含义不同，现在能看得很清楚

- 进程：列表 / 树形 / 详情三种视角，支持 9 种信号处置
